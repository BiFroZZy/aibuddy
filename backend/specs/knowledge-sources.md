# Источники знаний для демо и RAG

Этот файл фиксирует публичные материалы, которыми можно наполнить демонстрационную базу знаний. Перед использованием конкретного фрагмента сохраняются URL, заголовок, дата получения, команда/область доступа и версия или дата обновления источника.

## Материалы

| Источник | Что извлекать | Ограничения использования |
|---|---|---|
| [Чек-лист стажёра Авито](https://docs.google.com/spreadsheets/d/1gKfgQpSZj2F5J7BjBsmg7rukDXi_tRfwVqghgmViceV0/edit?usp=sharing) | Шаги адаптации и ссылки на материалы для выбранного направления; использовать приложенный PDF как фиксированную копию для демо | Не превращать чек-лист в универсальные обязательные правила; актуальность проверять по владельцу и дате |
| [AvitoTech Playbook](https://github.com/avito-tech/playbook) | Публичные процессы, стандарты, принципы разработки, материалы для студентов и обучения | Это открытый справочник, не внутренний регламент команды проекта; содержимое может устареть |
| [Avito.Tech](https://avito.tech/) | Общедоступное описание инженерной компании и разделы с техническими материалами и стажировками | Использовать для общего контекста компании, не приписывать это конкретной команде стажёра |

## Что учитывать при формировании ответов

- Сначала использовать чек-лист и документы, явно привязанные к demo-команде; публичный Playbook и Avito.Tech — дополнительные источники общего контекста.
- Каждый ответ по фактам сопровождать названием и ссылкой на использованный источник.
- Если источники расходятся, указывать расхождение и дату материалов; не выдавать предположение за правило.
- У ответа должны сохраняться метаданные происхождения фрагмента: URL, заголовок, дата получения, версия/дата источника и ACL.
- Публичные документы не дают права раскрывать данные других команд или персональные данные.
- Все локально подготовленные сценарии, mock-правила и синтетические сведения маркировать как демонстрационные. Не утверждать, что они являются текущими внутренними процедурами Авито.

## Предварительно релевантные разделы Playbook

- `students.md`: направления стажировок и общее описание программ для молодых специалистов.
- `development-principles.md`: проектирование, интерфейсы, документация, данные, отказоустойчивость, тестирование и эксплуатация.
- `processes-and-standards.md`: процессы, документация, MVP и обратная связь.
- `training-and-development.md`: обучение, технические тренинги и Tech Onboarding.

Использовать только те положения, которые действительно помогают ответить на вопрос стажёра; не копировать Playbook целиком в prompt.

## Локальный чек-лист

Входной материал: `Чек-лист  стажера - Материалы для всех.csv` (пользовательский файл). Он содержит описание задачи и период выполнения, включая периоды «1 неделя», «2 неделя», «1 месяц», «2 месяц» и «После 3-х месяцев». В чек-листе есть задачи для стажёра и отдельные поручения наставнику/куратору; импорт должен сохранять владельца задачи и не смешивать роли. Пустые периоды остаются пустыми, пока команда не назначит срок.

Материалы по защите персональных данных и конфиденциальной информации следует представлять как ссылки/напоминания на прохождение через одобренные внутренние источники. Сам CSV не содержит полного текста этих политик и не является основанием для их пересказа.
